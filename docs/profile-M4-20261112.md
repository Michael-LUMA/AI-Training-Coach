## 2. 计算契约

`compute_profile(user_id, database_url=None, *, now=None)`：重新计算并缓存；不足 3 次返回 None，移除旧缓存。
`get_profile(user_id, database_url=None, *, now=None)`：读取当日有效缓存；失效或跨日时按需重算。
`build_profile(records, *, now=None)`：无 I/O 的数值聚合，便于单独验证。

只使用通过现有云摘要白名单校验的记录，不接收/重建原始 session、GPS 或传感器 series。
“真实”在此仅指来源不是 simulated，并不等于服务器独立验证了传感器真实性。

- 默认只统计 ride；run/hike 不混入骑行基线。
- 至少 3 次正时长、已完成、非模拟骑行才生成画像；未来结束记录暂不计入。
- 习惯基线用按实际 started_at 排序的最近 30 次，不按上传顺序；累计和本周覆盖全部符合条件的摘要。
- 时长、距离、心率为每次摘要值的中位数；不是按采样点或时长加权的均值，也不是医疗阈值。
- usual_start_hour 按 UTC+08 的整点小时取众数，输出 0–23 整数；众数并列时取最小小时，结果不受上传顺序影响。
- 心率/距离各自不足 3 个有效观测时，其习惯基线保留 None，不补零；累计距离有 1 个有效观测即可计算，实测零距离保留为零。
- total_distance_km 是已提供距离的记录之和，不是缺失记录的推测总里程。
- 首发中国市场，暂固定 UTC+08、周一为本周起点；跨时区用户设置不在本轮范围。

画像包含：usual_start_hour、usual_duration_min、usual_distance_km、avg_hr_baseline、total_sessions、total_distance_km、this_week。
新增 sample_counts（baseline/distance/hr/total_distance/week_distance）说明每项使用的记录数量，避免把部分测量误解成全量证据。
this_week 包含 sessions、distance_km、duration_min。无本周记录时返回确切零；本周有记录但全部缺距离则 distance_km 为 None。
画像只有数值/空值/数值字典，没有自由文本、地址、评价词或模型生成结论；coach_notes 不复制进画像。

## 3. 更新、一致性与故障

- 新增摘要或实际删除记录：在同一事务内删除旧画像缓存；源数据和失效标记一起提交或回滚。
- 提交成功后安排后台计算；重复上传完全相同记录或删除不存在记录，不产生额外计算。
- 单个后台工作线程，最多 64 个待计算键；同用户待执行任务合并。执行中允许再次排队，避免遗漏随后发生的变更。
- 队列满/进程重启/后台计算失败时，不返回旧缓存冒充最新画像；下一次 get_profile 按需计算，无自动重试。
- 后台只输出固定故障提示，不记录 user_id、摘要、DSN 或底层异常文本。
- 摘要写入、删除、画像读写都先锁定所属 users 行；不同进程针对同一用户的更新通过 PostgreSQL 事务行锁串行，防止删除后旧画像被并发计算写回来。
- 服务正常退出先排空已接受的画像任务，再关闭数据库池。硬退出后，已提交的失效状态仍在库内，由下次读取恢复。
- 每天首次读取重新计算时间相关字段。当天缓存没有新写入/删除时最多保留至次日；未来结束记录不会在同一天仅因时钟推进而自动刷新。
- 缓存命中先校验字段白名单、数值和样本计数；损坏记录明确报错，不送入后续 AI。

## 7. M5 接线检查（只读核对，尚未实施）

以下是当前源码中已确认的接口差异，不是要求用户另买 API：

- 身份：云摘要路由通过 auth.whoami(token) 得到 user_id；聊天、复盘和实时链路尚未接入该身份。M5 必须先验证身份，再取该用户的记忆；不能把浏览器传来的 user_id 当授权，也不能把原有共享本地 JSON 当成云用户的兜底记忆。
- 数据：云端保存的是 summary 白名单，不含完整 session 所需的 series。应复用 cloud_rides.validate_summary 检查云数据，不能补造 series 来冒充 validate_session 通过；完整的当次 session 继续走原校验器。
- 聊天画像：ride_chat._profile_facts 当前只接收 {sessions, usual_start_hour, usual_duration_min}。M4 的 total_sessions 必须映射为 sessions，并投影这三个字段；不能把完整缓存字典原样传入。
- 聊天累计：现有 totals 必须包含全历史和本月次数/时长/距离六字段；M4 没有全部这些值，不能拿最近 30 次冒充全历史，也不能把缺失月统计补零。应由 M5 的源摘要聚合单独提供完整口径。
- 实时播报：ride_live._inputs 当前只投影固定白名单，没有 previous 字段。仅把 previous 塞进 live_facts 会被忽略，不能宣称接入成功。后续需最小化扩展 facts 的白名单与数字核验注册，保持 builder 签名和既有核验机制不变，并增加防历史数据冒充实时状态的测试。
- 上下文：任务包要求不超过 800 token。JSON 字符数不是精确 token 数；M5 必须给出可验证的预算策略，且不可截断 JSON 或删除计量单位来“达标”。
- 对话/笔记：本轮没有云对话存储和用户隔离笔记，M5 不可注入共享本地笔记或虚构 recent_dialog；对话持久化按 M6 独立推进。

因此本轮只交付 M4，不声称 M5 或线上记忆闭环已经完成。下一轮先完成数据库真实验收，再按这些契约接入；保持 qwen-max、builder 签名和匿名用户原有行为不变。
