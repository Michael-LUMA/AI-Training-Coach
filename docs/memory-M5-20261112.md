## 2. 统计与记忆口径

- 骑行、跑步、徒步分别统计；默认骑行。跑步/徒步不套用骑行画像。
- 排除模拟、零时长、未来未结束记录。复盘/实时对比仅使用当前开始前已完成、同运动类型的历史，排除当前自身。
- 最近 3 次趋势只保留既有 builder 实际使用的 duration_s / avg_hr；不是截取不完整 JSON，也不改变单位。
- 累计与本月数据从全部已校验源摘要聚合，不使用最近 30 条或列表接口的 100 条上限冒充全量。
- 任何纳入统计记录缺少距离时，完整累计距离为 None，不把缺失当零或报告部分和。
- 画像复用 M4 build_profile 的数值规则，同一批源摘要内计算，避免缓存与本次累计数据不同步；少于 3 次不生成习惯。
- 日期/周/月采用 UTC+08；周一起算。云端匹配日期投影不依赖服务器本机时区。
- 无需新增模型调用的检索支持：完整 ISO 日期、昨天/前天、上周、最近 30 天、上次、最长/最久/最短。尚未新增任意复杂自然语言日期解析，不声称覆盖所有历史问法。
- 日期范围命中超过 7 条，或完整命中集合无法在预算内保留时，返回明确 400，不截成部分条数冒充总数。

## 3. 数值核验与接口适配

- 三个 builder 函数签名、SYSTEM_PROMPT、LLM 请求逻辑均不变；没有换模型或改 qwen-max 配置。
- summary-only 云端记录通过 cloud_rides.validate_summary 校验，不伪造 series 来骗过 validate_session。
- 内部 SummarySession 仅是已验证云摘要的类型标记，不能从 JSON 提交来绕过本地记录校验。builder 进入时再次校验。
- 云摘要无法证明采样数和心率解耦，复盘不生成 sample_count 或 pw_hr_decoupling_pct；完整本地 session 仍走原校验。
- 实时 facts 新增 previous / profile 的严格白名单投影及原有数值注册。模型输出仍必须经过原 _verified_text 与安全词核验。
- 历史数字须在带“上次/此前/历史”的分句中；习惯数字须带“通常/平时/习惯”。当前分句只允许当前实时数值；历史与当前混合且有歧义则拒绝，不把历史心率冒充现在心率。
- 已选 session 的读取与上下文检索之间若记录变化，拒绝本次请求，避免另一份摘要绕过选中记录预算。

## 4. 800-token 预算策略

不把 JSON 字符数当精确 token 数，也不发付费请求来测 token。

- 使用默认 JSON 空格序列化，与现有 builder 一致，按 UTF-8 字节数计算保守上界；面向 byte-level BPE 的每 token 至少消费一个输入字节的预算假设，不依赖平均中英比例。
- 同时检查返回上下文与实际 builder 记忆投影，取较大值，再预留 32 字节拼接余量；必须 <=800。
- 不是整次请求 token 上限；system prompt、当前问题及本次实时/复盘数据不属于额外历史记忆。
- 优先完整保留命中的检索集合；按组舍弃低优先级趋势、周统计、习惯、上次或累计，不截字符串、不删计量单位来掩盖超限。
- 当前模型服务端 tokenizer 未下载做逐 token 比对，因此报告的是上述保守预算保证，不是供应商账单中的精确 token 数。若后续切换非 byte-level tokenizer，需要重新验证预算假设。

## 5. 请求接入边界

既有 POST 路径不变：

- /api/coach/ride/chat：原请求字段 + 可选 token。
- /api/coach/ride/review：session_id + 可选 token。
- /api/coach/ride/live：live_id / point / 可选 activity + 可选 token。

注意 token 是 /api/auth/register 获得的云身份凭证，不是 X-Coach-Token。私测 Basic 门禁、同源校验、X-Coach-Token、速率限制原样保留。

**前端 static/ 未修改，当前页面尚未自动注册、上传并附带云身份。** 旧页面仍按原本机模式运行；本轮没有承诺打开页面就能跨设备记忆。
