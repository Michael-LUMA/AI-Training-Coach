Mark cloud memory and data ownership — updated 12 November 2026

When cloud memory is enabled, the following cloud-specific rules override the legacy single-slot descriptions below. Mark automatically creates an anonymous cloud identity and stores its bearer token in this browser's localStorage. This is not a cross-device account. Anyone holding the token can access that identity's cloud data; do not share it. Device IDs cannot recover a lost token. Clearing site data may permanently remove your access.

The separate PostgreSQL service persists allowlisted activity aggregates, derived riding profiles, successful conversation text pairs and your cloud notes across application container restarts. Complete GPS tracks, raw sensor series and audio are not part of this cloud memory database or its export. Live assistance and navigation may transiently process location; speech and model providers receive the content needed for explicitly invoked functions. Conversation prompts can include up to five recent conversation rounds and the relevant user's aggregate context. Other configured AI providers may be used according to the server routing configuration; this release is configured for Qwen.

The cloud data panel in Mark and the ride workbench exports all four cloud categories for the current identity. Permanent deletion requires a warning confirmation and the phrase “删除云数据”; the server then hard-deletes the identity, aggregates, profiles, conversations and notes in one transaction and revokes the old token. No replacement identity is created automatically after deletion. These controls do not delete local tracks, drafts, downloaded exports, the legacy shared Intervals slot, or information retained independently by service providers. Database hard deletion is not a promise of physical erasure of storage media or provider backups.

Legacy local files and shared history are not silently assigned or migrated to new cloud identities. The private tester login remains required. Public account recovery, multi-device pairing and a production privacy/compliance review have not been completed.

Legacy Intervals shared-slot processing (not Mark cloud memory)

You paste your own Intervals.icu API key. The pilot stores it in a dedicated SQLite database on the host, encrypted by the available backend. Saving is refused if no encryption backend is available. The hosted pilot uses a masterkey backend, which is a constrained, unaudited standard-library construction, not audited encryption. The demo slot is shared and single: a key saved by another visitor replaces yours, and yours replaces theirs. Storage is ephemeral on the free host — the database (under .runtime/coach/ inside the container) is wiped on redeploy or restart, so you may need to reconnect. Do not treat the slot as private storage; revoke your key at Intervals.icu when you are done.

Only after you request an activity list or review does the pilot send authenticated requests to Intervals.icu. It processes activity details and streams, sport settings such as FTP and zones, and wellness data such as training load, sleep or resting heart rate where available.

Activity data and generated reviews are held temporarily in process memory and the current browser page. The legacy Intervals view has no persistent activity-data cache or review database; Mark cloud memory is described above. Responses use no-store; it does not deliberately save activity data in browser storage. It cannot guarantee erasure of host or browser session memory, or files you export yourself.

If you submit the optional waitlist, your lowercase email address and initial submission time are stored in a separate waitlist.db beside the credential database on the host. This file is not encrypted by the credential keystore and relies on filesystem permissions; it is equally ephemeral and is wiped on redeploy or restart. It records your opt-in for product updates, but this pilot sends no email and does not synchronize the list anywhere. First and repeat submissions receive the same acknowledgement.

Purpose and limits

Data is used to show your activities and produce the review you request. We do not sell your data and do not use it to train models. This pilot has no analytics, advertising SDKs, external fonts or CDN. Legacy Intervals reviews are rule-based. Mark review and conversation features can invoke AI services. In local-only mode, the ride workbench's "Ask Mark" Q&A sends your question — together with relevant aggregated metrics — to an external large-language-model provider (Alibaba Cloud DashScope, Qwen models) under its own policies. To support follow-up questions, your last 3 Q&A turns are held in server process memory only and included with the current question; they are discarded after 30 idle minutes, are never written to disk or any database, and vanish on restart.

Third parties

The current external integration is the Intervals.icu API, which receives your API key and requested activity identifiers/date ranges under its own policies. The pilot is hosted on Railway (railway.com) under its own policies; the host provides ephemeral container storage. An optional Creem webhook skeleton can accept signed server callbacks when the operator configures a secret. It stores event identifiers/types/timestamps and subscription identifiers, customer email when supplied, status and update time in a separate billing.db on the host (also ephemeral). It does not store raw callback bodies, card details or the webhook secret. Billing metadata is not encrypted by the credential keystore. There is no checkout, charging or paid-access enforcement in this pilot; no outbound Creem request is made. Provider terms, operator identity and launch data handling still require review before payments are enabled. Your browser, operating system, network, the host and Intervals.icu remain outside this app's control.

Retention and deletion

The saved key remains until the store is wiped. Storage on this free host is ephemeral: redeploying or restarting the service deletes the credential database, the waitlist and billing metadata. The legacy Intervals slot has no in-app delete button; Mark cloud identity deletion is available as described above. Revoke the API key in Intervals.icu at any time to make the stored copy useless; because the slot is shared, saving any other key also replaces yours immediately.

Closing the browser pages releases the temporary in-browser activity view; process memory is cleared on restart. Remove your own exports and backups separately; the ephemeral store does not create backups, does not guarantee physical secure erasure on the host, and does not remove data held by Intervals.icu or Railway.
